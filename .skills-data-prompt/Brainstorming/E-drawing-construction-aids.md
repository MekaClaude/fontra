# Category E: Drawing & Construction Aids

> Help beginners draw better outlines with smart tools and guides

## Context

The Glyphs sketching tutorial describes a workflow: sketch with double pencils → mark extremum points → digitize with straight lines → align nodes → add curves → adjust curvatures → iron out bumps. Many of these steps involve precision that beginners struggle with.

Fontra already has a Pen tool, Pointer tool, and Power Ruler. The Triangle Guardian tool provides geometric construction assistance. These can be enhanced with type-design-specific intelligence.

---

## Feature E1: Skeleton / Double-Pencil Drawing Mode

**Problem:** Per the Glyphs tutorial: "Take two pencils into your writing hand... the width of the nib is fixed." This is the fundamental technique for understanding thicks and thins in type design. No equivalent exists in digital tools by default.

**Implementation:**

### Concept
- A drawing mode where the user draws a single centerline path
- The system generates outlines on both sides of the centerline at a configurable nib width
- The nib angle is configurable (default: ~20° for Latin, matching the natural angle of a broad-nib pen)

### Technical Approach
- New tool: `edit-tools-skeleton.js`
- When drawing in skeleton mode:
  - User places points along the centerline (like the Pen tool)
  - Real-time preview shows the generated outlines
  - Outlines are generated by offsetting the path perpendicular to the tangent at each point
  - Handle the nib as a rectangle rotated by the nib angle — intersection of offset curves produces the outline

### Parameters
- **Nib width**: Adjustable (e.g., 60-80 units for a standard weight)
- **Nib angle**: Adjustable in degrees (0° = horizontal, 90° = vertical, default ~20° for Latin)
- **Cap style**: Round, square, or flat (for stroke endings)

### Conversion
- After drawing in skeleton mode, offer "Convert to outlines" which:
  - Generates the final outline paths
  - Removes the skeleton centerline
  - The resulting paths are standard editable outlines

### Reference
- Similar to LTTR/INK plugin for Glyphs (EUR 50+)
- This would be a major differentiator for Fontra as a free tool

**Files to create/modify:**
- New: `src-js/views-editor/src/edit-tools-skeleton.js` — skeleton drawing tool
- `src-js/views-editor/src/editor.js` — register the new tool
- `src/fontra/core/path.py` — add path offset/parallel curve utilities
- New: `src/fontra/core/skeleton.py` — skeleton-to-outline conversion logic

## Feature E2: Extremum Point Snap

**Problem:** Per the Glyphs tutorial: "In your sketch, you mark your corners, your extremum points, and the points where curves change into straight lines." Beginners often place points at arbitrary positions instead of at extremum points.

**Implementation:**

### Detection
- For each curve segment, calculate its extremum points (where the tangent is perfectly horizontal or vertical)
- This is standard bezier math: solve for t where dx/dt = 0 (vertical extremum) or dy/dt = 0 (horizontal extremum)

### Snap Behavior
- When the user is placing or moving a point with the Pen/Pointer tool:
  - If the point is within a threshold distance (e.g., 15 units) of a detected extremum position on an adjacent curve, snap to it
  - Show a visual guide (dashed line) at the extremum position when snap is active

### Visual Guides
- Show small crosshair markers at all detected extremum positions on the current glyph
- These guides update in real-time as the user edits

### Validation
- After the user finishes drawing a curve, check if it has extremum points without on-curve points
- If so, warn: "This curve has an extremum point at approximately (x, y) — consider adding a node there"

**Files to modify:**
- `src-js/views-editor/src/edit-tools-pen.js` — add extremum snap logic
- `src-js/views-editor/src/edit-tools-pointer.js` — add extremum snap during point movement
- `src-js/views-editor/src/visualization-layer-definitions.js` — add extremum guide layer
- `src/fontra/core/path.py` — add extremum calculation utility

## Feature E3: Curve Handle Normalization

**Problem:** Per the Glyphs tutorial: "Handles snap as soon as they are horizontal or vertical, which is what they need to be anyway around extremum points." Beginners leave handles at random angles near extremum points.

**Implementation:**

### Auto-Constrain
- When the user is dragging a handle with the Pointer tool:
  - If the handle is within a threshold angle (e.g., 5°) of perfectly horizontal or vertical, snap it to axis
  - Show a visual indicator (colored handle) when the handle is axis-aligned vs. free

### Validation Mode
- After editing, scan all handles in the glyph:
  - For handles near extremum points: flag if not horizontal/vertical
  - For handles at curve-to-line joins: flag if the tangent break is too large
- Show warnings in the Pro Advice panel

### One-Click Fix
- "Normalize handles" button that:
  - For each handle near an extremum, snaps it to the nearest axis
  - For handles at curve-to-line joins, aligns them to the tangent direction

**Files to modify:**
- `src-js/views-editor/src/edit-tools-pointer.js` — add handle axis snapping
- `fontra-coach/src/analysis/curve-inspector.js` — implement handle angle validation
- `src-js/views-editor/src/panel-pro-advice.js` — display handle warnings

## Feature E4: Node Positioning Guide

**Problem:** Per the Glyphs tutorial: "Ask yourself questions like: 'Is the top node above the right stem?' Place your nodes accordingly." Beginners don't know where to position nodes relative to the overall structure.

**Implementation:**

### Smart Alignment Guides
- When placing or moving a node, detect nearby structural elements:
  - Other nodes (vertical/horizontal alignment)
  - Stem edges (is this node aligned with a stem?)
  - Metric lines (baseline, x-height, cap-height)
  - Component boundaries
- Show alignment guide lines when the node is close to aligning with any of these

### Snap to Structural Grid
- Detect the dominant structural grid of the glyph:
  - Stem positions (left edge, right edge of each stem)
  - Key Y positions (baseline, x-height, cap-height, overshoot positions)
- Offer snap-to-grid behavior that constrains nodes to these structural positions

### Visual Overlay
- Show a subtle grid overlay based on the detected stem positions and metric lines
- Nodes that are "on the grid" show a small indicator
- Nodes that are "off the grid" show a warning indicator

**Files to modify:**
- `src-js/views-editor/src/edit-tools-pen.js` — add structural snap logic
- `src-js/views-editor/src/edit-tools-pointer.js` — add structural snap during movement
- `src-js/views-editor/src/visualization-layer-definitions.js` — add structural grid overlay
- `src/fontra/core/glyph_analysis.py` — expose stem positions for snap calculations
